# Archive block: a hard deny on reading archive/, in every agent

## Parent

#3

## What to build

The plugin enforces ADR 0008 in every repository: `archive/` is the human's alone. The block is a hard **PreToolUse deny**, and it applies the same way inside subagents and workflow agents as in the main session. A notice or injected context is not enforcement and is not part of this ticket.

- Denied for every model and agent:
  - reading, searching or listing into `archive/` (Read, Grep, Glob, notebooks);
  - editing, writing or deleting there;
  - moving or copying anything **out** of it;
  - Bash commands that name a path inside it to read it (`cat`, `rg`, `ls`, `git show <rev>:archive/…`, `git log -p -- archive`, …).
- Allowed: moving files **into** `archive/` (`mv` / `git mv` with the archive as destination).
- Every deny message says the archive is human-managed.

## Acceptance criteria

- [ ] Table-driven tests cover every denied tool and Bash form, the allowed move-in, and look-alike paths that must pass (e.g. `archived/`, `docs/archive.md`)
- [ ] In a live session, a Read, a Grep and a `cat` into `archive/` are refused
- [ ] In a live session, a **subagent's** Read of `archive/` is refused by the hook
- [ ] Recorded on this ticket from live runs: whether a repo-wide Grep returns matches from `archive/`, whether hooks fire for Workflow-tool agents, and whether they fire for the built-in `/code-review` fork. Every one that leaks gets a hard block closing it, or a stated reason why none is possible.
