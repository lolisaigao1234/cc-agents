# Trace edit gate: no edit without an open issue's branch

## Parent

#3

## What to build

The core of ADR 0006: in a repository that opted in, no file inside it can be edited unless the current branch belongs to an open issue.

- A Trace module answers "is this action traceable?" from git and GitHub state behind one interface, with real adapters and in-memory fakes for tests.
- Opt-in is a committed marker written by the `setup` skill. Without it, the trace checks do nothing. The archive block and the git guard are not affected.
- A launch-time environment variable set by the user turns the checks off. Nothing the model can set does.
- PreToolUse on file-editing tools denies an edit when the branch is the default branch, or its `<n>-` prefix names no open issue. The deny message names the pipeline step to return to.
- Two skills:
  - `trace`: model-invokable, about 30 lines. It maps Read → Track → Branch → Implement → Review → Update → Close onto Matt's skills and built-in commands.
  - `setup`: user-only. It writes the marker; adds the archive deny rule to project settings; checks `gh auth`, the triage labels, the glossary and the ADRs; and points to `/setup-matt-pocock-skills` when that is missing.

## Acceptance criteria

- [ ] Trace verdicts are tested through the module's interface with fake adapters: default branch, unlinked branch, closed issue, open issue, no marker, bypass set
- [ ] Edits outside the repository's working tree are never blocked
- [ ] In a live, opted-in session: an edit on `main` is refused, then allowed on a `gh issue develop` branch of an open issue
- [ ] Inside a subagent, the same edit is refused the same way
- [ ] `setup` is user-only and `trace` is model-invokable, and both pass plugin validation
