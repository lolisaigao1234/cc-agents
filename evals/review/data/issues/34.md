# trace.mjs: traced() treats a git timeout as untraced, letting the edit through

`realGit.traced` (`plugins/trace/scripts/lib/trace.mjs`, the `traced(root)` adapter) checks the working tree for `.claude/trace.json`, then asks git whether `HEAD`, `origin/<default>` or `<default>` has it. Any error, including `out of time asking git and GitHub` from the per-call deadline, is caught and returns `false`.

So in a repository whose marker exists only in `HEAD` or on the default branch (for example, deleted or moved in the working tree), a slow git makes the hook treat it as untraced and let the edit, commit or PR through. Elsewhere the trace fails closed ("Failing open here would let an untraced edit, commit or PR through", `hook.mjs`).

Found by the spec review of #32. The behaviour predates #32.

## Acceptance criteria

- [ ] When git cannot say whether the marker is in `HEAD` or the default branch, the edit, commit and PR gates refuse, naming the bypass, instead of treating the repository as untraced.
- [ ] A repository git positively says has no marker anywhere stays untraced, so untraced repositories are not gated.
- [ ] A test covers the timeout case.
