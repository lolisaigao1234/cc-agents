# trace.mjs: DEADLINE is set at module load, so long test files run out of time

`plugins/trace/scripts/lib/trace.mjs:749` sets `const DEADLINE = Date.now() + 20_000` once, at import. The hook is one process per call, so there it is one deadline per call, as intended (\"every call shares one deadline well inside the hook's timeout\"). Tests import the module in process: once a test file has run for 20s, every later git call throws `out of time asking git and GitHub`.

Seen in #31: `test/docs.test.mjs:331` ("a commit, or any git command that makes or moves commits, waits for every active ADR") fails under a full `npm test` when the earlier tests in that file are slow, and passes alone.

## Acceptance criteria

- [ ] The deadline starts per hook call (or per gate entry), not per module load, and still bounds every git and GitHub call within one hook call.
- [ ] A test shows a module that has been loaded for longer than the deadline still answers a fresh call.
- [ ] `npm test` passes repeatedly (say 5 runs in a row).
