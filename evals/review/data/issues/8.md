# Doc authority: forced, per-agent reads of the related docs

## Parent

#3

## What to build

ADR 0007: before an agent edits anything, or commits, it must have read every related doc in full. The model gets no discretion over which docs.

- The related docs, decided mechanically:
  - the glossary;
  - the linked issue with its comments (`gh issue view <n> --comments`);
  - every active ADR (one carrying an `Applies to:` glob line counts only for matching paths);
  - every `docs/` file the issue body links.
- Read means the whole file, by **that agent itself**. Chunks add up; a partial view does not count; a read goes stale when the file's content changes.
- Hard PreToolUse deny on file-editing tools and on `git commit`, in the main session and every subagent, listing exactly which docs are unread or stale.

## Acceptance criteria

- [ ] Tests cover chunked reads, partial views, stale hashes, `Applies to:` scoping, issue-linked docs, and per-agent isolation (the parent's reads do not count for a subagent)
- [ ] Unknown or undocumented hook input fails safe: it requires a re-read, never skips one
- [ ] Live: a fresh subagent cannot edit until it has read the docs
- [ ] Live: editing an ADR mid-session forces a re-read of it before the next edit
